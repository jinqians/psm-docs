# 中转（realm）

中转是在客户端和节点之间再加一台服务器：客户端连**中转机**，中转机把流量原样转发到**落地机**（真正运行节点的 VPS）。常见用途是用线路更好的机器做入口，或者多台落地机共用一个入口。PSM 用 [realm](https://github.com/zhboner/realm) 做端口转发。

在中转机上打开主菜单 **12. 中转管理（realm）**，第一次进入会提示安装 realm：

![中转管理菜单](/images/realm.zh.png){.shot}

## 添加一条中转规则

选 **添加中转规则**，按提示填写：

| 提示 | 例子 |
| --- | --- |
| 规则标识 | `hk-reality` |
| 本机监听端口 | `5000` |
| 落地机地址（IP 或域名） | `1.2.3.4` |
| 落地机端口 | `443`（落地机上 REALITY 节点的端口） |
| 是否同时转发 UDP | 落地是 Hysteria2、TUIC 这类 UDP 协议时选"是" |

之后客户端把节点地址改成**中转机的 IP 和本机监听端口**（上例是 `中转机IP:5000`），其余参数不变。

## 在面板里管理中转

服务器接入 [PSM 面板](/features/panel)后，中转也可以在面板的**中转**页里建，不用登录服务器：

| 字段 | 说明 |
| --- | --- |
| 入口服务器 | 规则装在这台机器上，客户端连的也是它 |
| 监听端口 | 入口机上监听的端口，面板会自动在防火墙放行 |
| 落地服务器 | 可选。落地机也在面板里时选上，只是把两端对应起来方便查看 |
| 落地地址 / 端口 | 入口机实际拨过去的地址，落地机不在面板里时照样能填 |
| 同时转发 UDP | Hysteria2、TUIC 这类基于 QUIC 的协议必须开 |

面板把规则下发给入口机上的 psm-agent，服务器上没有 realm 时先装好。删除中转时只收回面板自己开的端口，你手动放行的规则不会被动。

### 给中转加密

勾上**对这一跳加密（TLS）**，入口机到落地机之间的流量会再包一层 TLS，中间看到的不再是节点本身的协议特征。客户端到入口机这一段不受影响，客户端配置一个字都不用改。

- 落地机有证书：入口机这边填证书上的域名。
- 落地机用自签证书：勾上**接受自签名证书**，只保留加密，不验证对端身份。
- TLS 只包 TCP，UDP 仍然是明文转发。

## 其他功能

- **修改 / 删除 / 列出中转规则**。
- **状态报告**：中转机的资源占用、网速和到落地机的延迟，可以推送到 [Telegram](/features/telegram)。
- 服务状态、重启、日志、卸载。

记得在中转机的防火墙和云服务商安全组里放行监听端口（UDP 规则也要放行 UDP）。
